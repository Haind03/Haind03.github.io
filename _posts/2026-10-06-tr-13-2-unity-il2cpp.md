Ở bài trước bạn mở game Unity bằng Mono, thấy `Assembly-CSharp.dll`, kéo vào dnSpy là đọc được gần như source. Sướng. Rồi một ngày bạn mở một game khác, lục tung thư mục mà không thấy `Assembly-CSharp.dll` đâu cả, chỉ có một file `GameAssembly.dll` to đùng và một file lạ tên `global-metadata.dat`. Đó là lúc bạn gặp IL2CPP, và cuộc chơi đổi hẳn.

## IL2CPP làm gì với code C# của bạn

Mono giữ nguyên C# dưới dạng IL trong một DLL .NET, nên decompile ngon. IL2CPP (Intermediate Language To C++) thì khác: lúc build, Unity lấy IL của bạn, dịch sang C++, rồi biên dịch C++ đó thành machine code native nằm trong `GameAssembly.dll` (Windows), `libil2cpp.so` (Android), hoặc nhúng trong binary (iOS).

Hệ quả thẳng thừng: **không còn IL, không còn metadata .NET, nên dnSpy và ILSpy vô dụng.** Code giờ là native, phải mở bằng IDA hoặc Ghidra và đọc như C++. Đây là bước ngoặt y hệt NativeAOT của .NET (Bài 5.6) hay Nuitka của Python (Bài 7.5): managed hoá đã bị gỡ bỏ, bạn tụt về mức native.

Nghe nản, nhưng có một tin tốt rất lớn.

## global-metadata.dat, món quà của IL2CPP

IL2CPP cần biết tên class, tên method, tên field lúc chạy (để reflection, serialize, gọi tên...). Nó cất đống tên đó trong một file riêng: `global-metadata.dat` (thường ở `GameName_Data/il2cpp_data/Metadata/`).

Nói cách khác, machine code thì mất hết tên, nhưng cái bảng tên vẫn nằm sờ sờ trong một file. Nhiệm vụ của ta là ghép hai thứ lại: lấy tên từ `global-metadata.dat` gán vào đúng hàm trong `GameAssembly.dll`. Có tool làm việc này tự động.

## Il2CppDumper, con dao chính

**Il2CppDumper** nhận hai đầu vào là `GameAssembly.dll` và `global-metadata.dat`, rồi nhả ra:

- `dump.cs`: một file giả-C# liệt kê toàn bộ class, method, field kèm địa chỉ (RVA) của từng method trong binary. Đây là bản đồ của bạn.
- `script.json` và một script (`ida.py` hoặc `ghidra.py`): nạp vào IDA/Ghidra để nó tự đặt tên hàm theo metadata.
- Vài file phụ (`il2cpp.h` chứa struct) để import kiểu.

Quy trình gọn:

```
1. Tìm GameAssembly.dll và global-metadata.dat trong thư mục game.
2. Chạy Il2CppDumper, trỏ vào hai file đó.
3. Mở GameAssembly.dll trong IDA/Ghidra, đợi phân tích xong.
4. Chạy script Il2CppDumper sinh ra (ida.py / ghidra.py).
5. Giờ các hàm sub_xxx đã có tên thật kiểu PlayerController$$TakeDamage.
6. Đọc dump.cs để biết hàm nào đáng xem, nhảy tới RVA đó mà đọc logic.
```

Sau bước 5, trải nghiệm gần như quay lại Mono: bạn thấy tên hàm có nghĩa, chỉ khác là phải đọc pseudocode native (C) thay vì C# sạch. Vẫn hơn đứt việc bơi trong `sub_18004A2C0`.

## Cpp2IL, lựa chọn hiện đại hơn

**Cpp2IL** đi xa hơn Il2CppDumper: nó cố dựng lại IL (và từ đó là C# gần đúng) từ machine code, không chỉ gán tên. Với các phiên bản Unity mới mà Il2CppDumper đôi khi vấp (format metadata đổi liên tục theo version), Cpp2IL thường xử lý tốt hơn và cho output gần source hơn. Có cả plugin xuất ra dạng mở được bằng dnSpy.

Thực tế: thử Il2CppDumper trước vì nhanh và ổn, nếu nó không parse được metadata (báo lỗi version) thì chuyển sang Cpp2IL. Hai tool bổ trợ nhau.

## Cái bẫy hay gặp

- **Sai phiên bản metadata.** `global-metadata.dat` có số version thay đổi theo bản Unity. Tool cũ không đọc được bản mới. Cập nhật tool, hoặc thử Cpp2IL.
- **Metadata bị obfuscate.** Một số game cố tình mã hoá hoặc xáo `global-metadata.dat` (header bị đổi, string encrypt) để chặn Il2CppDumper. Khi đó phải khôi phục metadata trước (có fork tool chuyên trị, hoặc dump từ bộ nhớ lúc game đang chạy, tương tự tư duy unpack ở Phần 14).
- **Tìm nhầm file.** Trên Android, `GameAssembly.dll` tương đương là `lib/arm64-v8a/libil2cpp.so` trong APK, còn `global-metadata.dat` nằm trong `assets/bin/Data/Managed/Metadata/`.

## Vì sao nền tảng native là cứu cánh

Khi đã dumped và gán tên xong, việc còn lại thuần tuý là đọc code native ARM64 hoặc x64. Đây chính là lúc Phần 1 tới Phần 4 trả công: bạn cần đọc được assembly, nhận ra struct, hiểu con trỏ. IL2CPP không khó vì nó bí hiểm, nó chỉ đưa bạn từ sân chơi managed dễ dãi về lại sân native. Ai vững native thì IL2CPP chỉ là thêm một bước dump ở đầu.

## Checklist ghi nhớ
- Không thấy `Assembly-CSharp.dll` mà có `GameAssembly.dll` + `global-metadata.dat`: đó là IL2CPP.
- IL2CPP dịch C# sang C++ ra native, nên dnSpy vô dụng, phải dùng IDA/Ghidra.
- `global-metadata.dat` giữ tên class/method/field, là chìa khoá để lấy lại tên.
- Il2CppDumper ghép binary + metadata, sinh `dump.cs` và script gán tên cho IDA/Ghidra.
- Cpp2IL mạnh hơn với Unity mới và có thể dựng lại gần IL.
- Metadata obfuscate hoặc sai version là hai cái bẫy lớn nhất.
