Trong các loại game để tập reverse, Unity bản Mono là dễ nhất, dễ tới mức gần như gian lận. Lý do: toàn bộ code gameplay nằm trong một file .NET tên `Assembly-CSharp.dll`, mà .NET thì bạn đã biết từ Phần 5 là decompile ra gần như source gốc. Mở bằng dnSpy, bạn đọc được tên class, tên biến, logic, rồi sửa thẳng và lưu lại. Không cần đụng tới một dòng assembly nào.

Bài này giả định bạn làm trên game offline, single-player của chính mình. Sửa game online là chuyện khác hẳn về cả kỹ thuật lẫn pháp lý, không nằm trong phạm vi ở đây.

## Nhận ra một game là Unity

Dấu hiệu nằm ngay trong thư mục cài đặt. Cạnh file exe của game luôn có một thư mục tên `<TênGame>_Data`. Mở nó ra, bạn phân biệt được backend ngay:

- Có thư mục `<TênGame>_Data/Managed/` chứa đầy file `.dll`, trong đó có `Assembly-CSharp.dll`: đây là backend **Mono**. Đây là trường hợp của bài này, và là trường hợp dễ nhất.
- Có file `GameAssembly.dll` (to vật vã) cạnh exe và file `global-metadata.dat` trong `il2cpp_data/Metadata/`: đây là backend **IL2CPP**. Code đã bị biên dịch sang native, khó hơn nhiều, để dành bài [13.2](/posts/tr-13-2-unity-il2cpp/).

Chỉ cần liếc xem có `Managed/Assembly-CSharp.dll` hay có `GameAssembly.dll` là biết mình đang gặp loại nào. Detect It Easy kéo vào `Assembly-CSharp.dll` cũng xác nhận đây là .NET assembly.

## Mở Assembly-CSharp.dll trong dnSpy

Đây chính là quy trình Phần 5, áp vào game. Kéo `Assembly-CSharp.dll` vào dnSpy (có sẵn trong repo này tại `dnSpy-net-win64`). Bạn thấy cây namespace và class y như một project .NET bình thường.

Điểm khác biệt của Unity: phần lớn class gameplay kế thừa `MonoBehaviour`, và logic nằm trong các method quen thuộc của Unity:

- `Start()` chạy một lần khi object được tạo.
- `Update()` chạy mỗi frame.
- `Awake()`, `OnEnable()`, `OnTriggerEnter()`, và các callback khác.

Biết điều này giúp bạn khoanh vùng nhanh. Muốn tìm logic cộng điểm mỗi frame? Nhìn vào `Update()`. Muốn tìm khởi tạo máu ban đầu? Nhìn `Start()` hoặc `Awake()`.

## Đi tìm giá trị cần sửa

Giả sử bạn muốn tìm chỗ quản lý vàng (gold). Cách hiệu quả nhất vẫn là đi từ cái dễ nắm nhất:

1. **Tìm theo tên.** dnSpy có Search (Ctrl+Shift+K). Gõ `gold`, `coin`, `money`, `health`, `hp`. Lập trình viên game hiếm khi obfuscate tên biến ở bản Mono, nên bạn thường thấy ngay `public int gold;` hoặc `private float health;`.
2. **Dùng Analyze.** Chuột phải vào field `gold`, chọn Analyze, xem "Used By" để biết method nào đọc/ghi nó. Hàm trừ vàng khi mua đồ, hàm cộng vàng khi nhặt, tất cả hiện ra.
3. **Đọc logic.** Vào method kiểm tra kiểu `if (gold >= price)`. Đây là chỗ bạn can thiệp.

## Sửa và lưu lại

dnSpy cho sửa trực tiếp bằng C# (Edit Method), đúng như [Bài 5.4](/posts/tr-5-4-patch-il-csharp-dnspy/). Vài kiểu sửa kinh điển:

```csharp
// Gốc: trừ vàng khi mua
public bool TryBuy(int price) {
    if (gold >= price) { gold -= price; return true; }
    return false;
}

// Sửa: luôn mua được, không trừ vàng
public bool TryBuy(int price) {
    return true;
}
```

Hoặc với máu, sửa `Update()` để ghim máu về tối đa mỗi frame (god mode thô sơ):

```csharp
void Update() {
    health = maxHealth;   // thêm dòng này
    // ... phần còn lại
}
```

Sau khi sửa, chuột phải vào module rồi Save Module, ghi đè `Assembly-CSharp.dll`. Chạy lại game là thấy hiệu lực. Nhớ backup file gốc trước khi ghi đè, luôn luôn.

Nếu game ký strong name hoặc có kiểm tra toàn vẹn thì phải xử lý thêm, nhưng phần lớn game indie Mono không làm chuyện đó.

## Trích asset với AssetStudio

Ngoài code, bạn có thể muốn xem hoặc trích tài nguyên: texture, model, audio, text. Chúng nằm trong các file `.assets` và asset bundle trong thư mục `_Data`. **AssetStudio** (hoặc AssetRipper) mở các file này, liệt kê và export tài nguyên ra định dạng thường. Hữu ích khi bạn muốn hiểu dữ liệu game, tìm chuỗi text ẩn, hay chỉ tò mò.

## Vì sao Mono dễ hơn nhiều so với IL2CPP

Tất cả là nhờ Mono giữ nguyên IL và metadata trong `Assembly-CSharp.dll`, đúng như mọi .NET assembly. Khi nhà phát triển chọn IL2CPP, code C# bị dịch sang C++ rồi biên dịch native thành `GameAssembly.dll`, tên bay gần hết, và bạn mất món quà decompile ra source. Đó là lý do bài tiếp theo phải dùng tới một bộ công cụ hoàn toàn khác.

## Checklist ghi nhớ
- Unity có hai backend: Mono (`Managed/Assembly-CSharp.dll`, dễ) và IL2CPP (`GameAssembly.dll`, khó).
- Mono là .NET: mở dnSpy đọc gần như source, sửa và Save Module.
- Logic gameplay nằm trong class kế thừa `MonoBehaviour`, xem `Start()`/`Update()`.
- Đi từ tên biến (gold, health) qua Search và Analyze để tới logic.
- AssetStudio để trích texture/model/audio/text.
- Luôn backup file gốc. Chỉ làm trên game offline của chính mình.
